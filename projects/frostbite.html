What it looks like

This is a demo copy. I rebuilt it from the front-end code with made-up sample data, so the numbers are not mine. It runs in your browser, and you can add, edit and delete entries to try it, but nothing is saved. Open the interactive demo.

What it does

Accounts that match real life

Cash, savings, credit cards and investments, sorted into groups, with an option to override an account's balance.

Three kinds of entry

Income, expenses and transfers. A transfer moves money between two accounts and doesn't need a category.

Categories with icons

Separate income and expense categories, each with an icon and an optional offset flag.

Fast to search and filter

Search from the top bar, or filter by type, account and category with select-all and clear on each list.

A credit card view

Its own tab for credit cards, next to the transactions and accounts tabs.

Works on any screen

The one-page interface is designed for desktop, iPad and iPhone, in Chrome, Safari and Firefox.

How it's built

A small Express server with SQLite through better-sqlite3 and a single-page front end. The database creates its own tables and seeds defaults on first run, and the API has three routes for accounts, categories and transactions. Version 5 was a hardening release: the server redirects HTTP to HTTPS, generates its own certificates, and only accepts requests from the origins I list.

  • Node.js
  • Express
  • SQLite
  • better-sqlite3
  • HTTPS
  • GitHub Actions

Every push runs UI checks and API checks in GitHub Actions, and a final job blocks the merge if either fails.

Why it stays private

It holds my own financial data and the details of how I reach my server, so the repository is private and there is no code link. The demo uses the app's front-end code on made-up data, so no real numbers appear.
